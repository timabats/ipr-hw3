# Запуск
Если у используемого пользователя нет доступа к Docker daemon, то ко всем командам, начинающимся на `docker`, надо добавить `sudo`.

## 1) 4 балла:
Сборка и запуск (из корня репозитория)
``` bash
docker build -t hw3:1 .
docker run -d --name hw3 -p 127.0.0.1:8080:8000 -e GREETING="Hello from Docker!" hw3:1 
```

Просмотр счётчика в более красивом формате
```bash
curl -s 127.0.0.1:8080 | jq
```

Инкремент
```bash
curl -s -X POST 127.0.0.1:8080/increment | jq
```

Просмотр логов
```bash
docker logs hw3
```

[Пример логов](reports/logs_4points.txt)

## 2) 6 баллов:
Порт и приветствие можно настроить в [`.env`](./.env), пример в [`.env.example`](./.env.example).

 Запуск
```bash
docker compose up -d --build
```

Остановка без удаления volume
```bash
docker compose down
```

Остановка с удалением volume
```bash
docker compose down -v
```

Просмотр счётчика и инкремент (аналогично предыдущему пункту, но с новым портом)
```bash
curl -s 127.0.0.1:1234 | jq
curl -s -X POST 127.0.0.1:1234/increment | jq
```

[Проверка, что после пересоздания контейнера счётчик сохраняется](reports/console_dump_6points.txt)

## 4) 10 баллов:
Запускать скрипт необходимо из корня репозитория, с `sudo` для доступа к движку докера (если у пользователя нет доступа изначально). По умолчанию скрипт использует порт `6767`, если он занят, скрипт падает с сообщением об этом. Указать другой порт можно первым аргументом скрипта
```bash
./scripts/check.sh
./scripts/check.sh 8000
```

Скрипт собирает новый образ, проверяет поведение, в случае успеха делает копию базы данных в [`backup/data`](backup/data). Независимо от результата удаляет контейнер, volume и образ. При ошибке выводит этап, на котором она произошла.

[Пример успешного запуска скрипта 2 раза подряд](reports/console_dump_10points.txt)
